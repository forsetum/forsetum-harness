# Modules

The manifests are the source of truth. English and Indonesian currently have
the same 11 modules.

## Engineering

| Module | Purpose | Intended use | Major areas |
|---|---|---|---|
| `web-fullstack` | Production web application governance | Database-backed apps, APIs, microservices | Architecture, server, API, security, operations, recovery |
| `web-starter` | Lightweight web project governance | MVPs, prototypes, static previews | Architecture, app, persistence, testing |
| `mobile-app` | Mobile delivery governance | Native and cross-platform apps | Platform, architecture, store, signing |
| `cli-automation` | Command-line and automation governance | CLI tools, jobs, daemons, data automation | Interface, runtime, pipeline, daemon |
| `app-maintenance` | Brownfield change governance | Existing applications and isolated extensions | Context, extensions, compatibility, triage |
| `it-infra-ops` | Infrastructure operations governance | On-premises and virtual infrastructure | Inventory, maintenance, incidents, changes, backup |

## Additional Domains

| Module | Purpose | Intended use | Major areas |
|---|---|---|---|
| `landing-page` | Conversion page governance | Marketing pages and static sites | Copy, layout, assets, hosting |
| `research-analysis` | Research governance | Market research and decision memos | Methodology, sources, analysis, summary |
| `content-marketing` | Editorial governance | SEO, content, and social publishing | Calendar, SEO, voice, distribution |
| `sales-outreach` | B2B outreach governance | Prospecting and deal workflows | ICP, pipeline, messaging, CRM |
| `general-office` | Office operations governance | SOPs, reporting, and procedures | Procedures, deliverables, resources, reporting |

Each module overlays the universal governance core. The bilingual manifests
and directory parity are validated by the repository validator.
